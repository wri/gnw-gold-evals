GOLD evaluator map

What each check measures, which evaluator produces it, and which of the five buckets it answers for — plus the case shapes that switch each check on.

Every check is tri-state 1.0 pass · 0.0 fail · null not evaluated. Checks are opt-in: a blank expected field means the check abstains, not that it passes.
Row verdicts pass · fail · error (API/judge failure — never counted as fail) · uncovered (nothing evaluated — never counted as pass).
Badges DET deterministic JUDGE LLM-judged (claude-haiku-4-5, temp 0) SHARED failure straddles two buckets INFO-ONLY reported, never gates a verdict.
Multi-turn per-turn checks flatten to t1./t2. prefixes; state_delta asserts changes between turn snapshots.
RETRIEVAL

Understanding the question

Did the agent extract the right things from the prompt — place, dataset, dates — and actually fetch the data?

checkevaluatorswitched on bywhat it measures
aoi_id_match DETaoiexpected.aoi_ids The agent resolved exactly the expected GADM/KBA area set (set equality, ;-separated). Expected-but-none-resolved scores 0, not null.
dataset_id_match DETdatasetexpected.dataset_id The right dataset was selected. ; lists acceptable alternatives (e.g. 8;10) — any one matches.
dataset_parameter_match DETdatasetexpected.dataset_parameters Dataset parameters (e.g. canopy-cover threshold) match on name + values.
context_layer_match DETdatasetexpected.context_layer The right context layer; no_selection asserts none was chosen.
date_extraction DETdate_extractionexpected.start_date + end_date The agent parsed the requested time window out of the prompt. Set only on date-scoped datasets (alerts, imagery) — annual datasets always pull their full range.
data_pull_exists DETdata_pullimplied: answer set, or insight widget expected A real data pull happened whenever the expectations imply one (expects_data_pull(); false when a clarification is expected instead).
pull_source_match DETguardsexpected.dataset_id (guard) The pulled statistics entry's dataset_id equals the expected dataset — whole-value equality, never substring matching. Abstains (with the source recorded) when the payload carries no id.
answered_without_data DETguardsimplied (guard) Tripwire: a substantive answer (≥80 chars) with no pull and no dataset selected scores 0. A refusal is not a violation.
state_delta DETmultiturn runnerturns[n].deltas Between-turn assertions: changed / retain / absent on snapshot fields (aoi_ids, dataset_id, dates, …). Field names are schema-validated, so typos fail at authoring time.

SCOPE

The right amount of work

Clarify when ambiguous, suggest when asked to suggest, analyse when asked to analyse — no more, no less.

checkevaluatorswitched on bywhat it measures
scope_match DETscopeexpected.scope The route the agent took (analyse / suggest / clarify / refuse) equals the expected one.
clarification_requested JUDGEclarificationexpected.clarification Tri-state: TRUE — it must ask; FALSE — it must not; blank — not evaluated.
suggested_datasets_match DETsuggested_datasetsexpected.suggested_datasets Suggestions are a non-empty subset of the acceptable set (0;1;2;3;4): at least one hit, nothing outside it.
nudge_match DETnudgeexpected.nudge_type / nudge_options The nudge is one of the acceptable types (OR), and its options cover the expected ones (substring, case-insensitive).

INFO-ONLY also includes date_coverage (did the pulled data cover the requested window) — permanently informational because annual datasets always pull their full range and slice in code, so the recorded window flips between runs without the answer being wrong.

The case shapes (cases/v2 — 114 cases, 16 groups)

A case is one YAML file; every non-empty expected key switches on the matching checks above. These five real archetypes cover the shapes in use.

Direct analysis 1-002 · direct

query: How much of Sao Paulo was impacted
  [by] disturbance alerts in H2 2024 ...?
expected:
  aoi_ids: BRA.25_1
  dataset_id: '11'
  start_date: '2024-07-01'
  end_date: '2024-12-31'
  answer: 1,319,600 hectares
  scope: analyse

Lights up: aoi_id_match dataset_id_match date_extraction data_pull_exists agent_answer charts_answer scope_match + always-on guards/chart checks. The workhorse shape: one question, one pinned window, one number.

Suggestion + clarification 1-084 · dataset-suggestion

query: Show me trends in natural land
  loss in Gabon
expected:
  aoi_ids: GAB
  clarification: 'TRUE'
  suggested_datasets: 0;1;2;3;4
  text: Provides good reason for each
    dataset suggestion ...
  scope: suggest

Lights up: clarification_requested suggested_datasets_match expected_text_match scope_match. Because a clarification is expected, expects_data_pull() is false — no pull demanded.

Multi-turn delta mt-001 · multiturn

turns:
- query: Show me recent disturbance
    alerts in Puri
  expected: { clarification: 'TRUE' }
- query: I mean the Puri district in
    Odisha, India
  expected: { scope: analyse }
  deltas:
    changed: [aoi_ids]

One thread, sequential turns; checks flatten to t1.clarification_requested, t2.scope_match, t2.state_delta (the AOI must actually change after the user disambiguates). A turn that errors aborts the conversation rather than polluting later turns.

Dashboard 1-096 · dashboard

query: Create a dashboard for brazil
expected:
  aoi_ids: BRA
  dashboard_created: 'TRUE'

Lights up: dashboard_created dashboard_aoi_match (+ widget checks when dashboard_widgets is set). Map-only dashboards don't demand a data pull. Staging-only capability — prod lacks dashboards.

Nudge / disambiguation 1-105 · nudge

query: Select an area named Puri
expected:
  text: Asks the user to choose between
    Puri in Odisha and Puri in Uige ...
  nudge_options: Uíge, Angola;Odisha, India
  scope: clarify

Lights up: nudge_match expected_text_match scope_match. The structured nudge state and the prose behaviour are checked separately — an agent that clarifies in prose but sends no nudge fails half of this.

Deeper detail worth knowing

  • Null is a decision, not an accident. Every check's spec says whether an absence is null (not applicable) or 0.0 (failure). The four historic "vanishing" cases — no AOI resolved, no chart produced, judge exception, empty dashboard — now fail or surface as errors instead of silently abstaining.
  • Shared checks never attribute blame. agent_answer failing could be Analysis or Explanation; the bucket table counts dedicated and shared populations separately rather than guessing.
  • Verdicts exclude noise by construction. Info-only checks and errored rows never enter pass/fail; a row with zero evaluated checks is uncovered, not passing. Errored rows are also excluded from bucket tallies.
  • The console [FAIL] print is coarser than the report — it fires on any zero-valued check including info-only ones; trust the bucket report and diff_runs.py, not the live print.
  • Identity: a case's uid hashes query + expectations (notes and status don't count); results key on uid, so an edited case can never inherit old scores. Runs are comparable iff caseset_version matches; regressions are computed over the uid intersection.
  • Held cases still execute: the default run filter excludes only not doing — todo cases (1-062, mt-007) run and report, they're just flagged as not yet curation-approved.
