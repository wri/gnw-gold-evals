## 3. The harness

- **`chart_well_formed` and the rescore.** The agent now sends wide-format
  charts: `seriesFields` names the data columns and `yAxis` is a label. The
  check read `yAxis` as a data key and failed 59 attempts on 23 questions
  ("yAxis references field 'area_ha' absent from data"), all stacked bars of
  alerts. Fixed in bef0cdd; `tools/rescore_run.py` recomputed that check and
  the record carries `rescored` and `methodology_note`. Verified: the as-scored
  copy and the record differ only in `chart_well_formed` (59 attempt values, 23
  question values, 19 verdicts), and the fixed check run again on the 800 saved
  states gives 469 pass, 0 fail.
- **No question fails `chart_well_formed` after the fix.** Four of the 23 did
  not change verdict. `ch-mon-011` still fails: two attempts report totals
  since December 2023 for "recently", and the third fails only the period
  check. `ch-mon-058` still fails: two attempts ask which dataset. `ch-mon-040`
  and `ch-mon-061` passed before and after.
- **`chart_integrity` does not see wide-format series columns.** It looks for
  nulls in the `xAxis` and `yAxis` fields only. On a wide chart `yAxis` is a
  label, so the columns that hold the values are never checked. 173 of the 624
  charts in this run are wide. None has a null in a series column. 44 have
  rows with a series column absent (dates with no alerts at one confidence
  level); I did not check how the frontend draws those.
- **The number reader does not scale "GtCO₂e" written with a subscript 2.**
  "-4.02 GtCO₂e" is read as -4.02; "GtCO2e" is read as billions. It failed
  `figure_match` on `ch-comp-043` attempt 2 and `ch-quant-188` attempt 3. No
  verdict changes; `ch-comp-043` would be right 3 of 3.
- **`answer_period_match` (judged) fails replies that state the asked
  period.** It is the only failed check on 11 attempts. By my reading of the
  replies, 10 are false: `ch-comp-031` (all three), `ch-comp-168`,
  `ch-mon-011`, `ch-quant-033`, `ch-quant-036`, `ch-trend-029`, and
  `ch-quant-164` (two). Six are emission-factor replies that add a note on the
  dataset's assessment period (2001 to 2020); three are inside the case's own
  date tolerance. If they
  are false, `ch-comp-031`, `ch-comp-168` and `ch-quant-164` pass: 214 of 267
  (80.1%). Not rescored: a judged check cannot go through `rescore_run.py`,
  and a person should confirm my reading first.
- **Replies that are not replies.** The harness takes the last message of the
  state as the answer. On three attempts that message is tool output, and one
  of them was scored right (`ch-comp-163` attempt 1). On two it is empty; they
  were scored wrong but not counted as no reply. So "1 of 801 got no reply"
  understates it: 3 attempts left the user with no text. I could not tell from
  the saved states what the user would have seen on the other three.
- **The one no-reply attempt and the one ReadTimeout are the same attempt:**
  `ch-causal-001` attempt 2, after 245.9 s. There was no block of timeouts
  (5 workers). 7 attempts took over 200 s.
- **The judge splits on the same reply.** `ch-port-016` got near-identical
  replies on all three attempts and passed one. `expected_text_match` has a
  flake std of 0.12 in `flakiness.py`.
- The run record keeps judge reasons for the last attempt only, so an earlier
  attempt's failure has to be reread from the saved state.
