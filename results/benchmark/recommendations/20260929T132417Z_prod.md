## Headline

- **86% of benchmark questions got a complete answer, and 92% of those were right on every trial.** Nothing errored.
- **The biggest failure mode is over-asking: 7 of the 14 failures.** The agent sends a `dataset_choice` nudge ("which dataset would you like?") when one dataset clearly fits. This happens across three types:
  - Dataset: `ch-dataset-003`, `-006`, `-033`, `-178`.
  - Quantification: `ch-quant-052`, `-063`.
  - Comparison: `ch-comp-021`.
  - `ch-quant-052` is the clearest example: the reply calls Forest GHG net flux "the best match for your request" and then asks the user to pick anyway.

  The same RAG picker behaviour was the top failure in the 25 September jev comparison (`results/challenge/recommendations/20260925T121040Z_local.md`). The failure is scored as **retrieval** because `dataset_id_match` fails. In stakeholder terms it is closer to "didn't do the work" (scope), and the page copy should say so.
- **Every Trend member passed.** Treat that as a ceiling warning rather than a triumph: the numeric sets are scored retrieval-first (see "Before the freeze").

## Recommendations

**Upstream (project-zeno):**

1. **Over-nudging in `pick_dataset`** is the single largest lever: 7 of 14 failures, about 7 points of North Star. The fix direction from the jev work applies here: nudge only when two datasets are genuinely equally good, not when one is the best match. File it with these seven case ids as evidence; `ch-quant-052`'s reply text is the most persuasive.
2. **sLUC comparisons fall back to blogs** (`ch-comp-040`). The agent never considers dataset 9 for an emission-factor question and answers from `search_blogs` instead. That is an unmet question presented as an answer.
3. **Scope leak on a map-only prompt** (`ch-dataset-100`, trial 1): pulling global data for "show me" is the behaviour the Dataset set's `forbidden_tools` guard exists to catch.
4. **Chart record join** (`ch-comp-074`): null axis fields in a two-period comparison chart. The answer itself was right.

**Case set (CHALLENGE, before re-sampling):**

5. **Verify `ch-aoi-030` and `ch-aoi-154`.** The AOIs the agent picked (34808/14072 for Mabira; 2281 for Tumucumaque) may be legitimate duplicates of the same place across sources, such as a KBA and a WDPA entry. If so, the expectation should accept them (`;` alternatives). If not, these are real picker misses. Either way this must be settled before freezing: an expectation fix mints a new uid.
6. **`ch-quant-008`** expects a 2001-2025 window from an undated prompt. Either drop the date expectation or add "since 2001" to the query.
7. **`ch-dataset-178`** ("Show plantations on the map") pins `select` in the ambiguous cohort. The nudge the agent gives is defensible, so re-check whether this member belongs in a benchmark at all.

**Harness:**

8. **A check that runs on only a minority of trials can decide the verdict.** `ch-dataset-100` fails on `chart_integrity` because it evaluated on trial 1 only, the one trial with the scope leak. The scope check itself (`forbidden_tools_absent`) failed on only 1 of 3 trials, so majority voting passed it. The row's verdict and its primary-failure stage (analysis) therefore come from a single trial. This is existing majority-merge behaviour (`cli.merge_trials`) shared with GOLD, so it's not a benchmark bug, but it distorts attribution. Worth a separate look: for example, count a conditional check towards the majority only when it evaluated on a majority of trials.
9. **The coverage matrix undercounts reachable stages.** Member `stages` come from implied checks only, but conditional checks (`chart_integrity`, `answer_traceability`, `chart_well_formed`) evaluate whenever a chart exists. That is why two Analysis failures appear in types whose matrix shows 0 Analysis members. The matrix answers "which stages each case is designed to test", and the page copy should use that wording.

## Before the freeze (November)

- **The numeric types are retrieval-only.** Quantification, Comparison and Trend members assert dataset, AOI, dates, context layer and data pull, with no expected numbers and no scored explanation. Trend's 100% means "fetched the right data 20 times". The Phase 2 numeric-fidelity evaluators have to land, and the version be re-sampled (new expectations mint new uids), before the North Star can mean "complete accuracy" for those types.
- Apply the case fixes in items 5 to 7 to CHALLENGE first, then re-sample.
- Re-run canonically after the re-sample. That run becomes the first published North Star, and this run stays in the ledger as the draft baseline.
