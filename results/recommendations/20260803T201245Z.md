## For the agent team (file upstream)

   regression to chase.** `dashboard_created` is 0.0 on all 3 trials of 1-096,
   1-097, 1-098, 1-099, 1-100, 1-101 and mt-008 t2, while 1-102 (which expects
   `dashboard_created: FALSE`) passes. The artifacts settle the cause: the agent
   never calls a dashboard tool at all — tool calls are `read_skill, pick_aoi,
   pick_dataset, pull_data, generate_insights`, and `dashboard_widgets` is `null`.
   On one trial it simply asks which indicators to include. Per `docs/PLAN.md` §6
   these zeros must never be read as agent regressions; all seven rows now carry
   an `env_gated` note (added this cycle) so that is legible in the ledger.
   **Confirm whether dashboards are expected on staging at all**, because until
   they are, this is a permanent 7-row deduction from the headline.
2. **Under pushback the agent reaches for the blog, not the data — now caught
   deterministically.** mt-007's turn 2 fails `t2.web_fallback` on two `wri.org`
   citations. The numeric anchor added to T2 this cycle is doing its job: the
   agent *does* restate 885,238 ha, so it is not capitulating on the figure, but
   it justifies itself from web sources rather than the pull. This is the
   misleading-behaviour class in its multiturn form, and it is no longer resting
   on a judge whose verdicts ran 1.0/0.0/1.0.
3. **Chart mis-join persists — 1-043 and 1-060.** `chart_integrity` reports
   *"xAxis field 'driver' is null in 3/10 records — mis-joined record sets"*. Two
   differently-shaped record sets concatenated, null-padding the axis fields the
   chart itself references. `chart_integrity` is the most stable check in the suite
   (0.99, ±0.01), so the verdict is trustworthy. **This remains the single
   highest-value upstream fix** for the pass rate.
4. **1-030 still answers from the blog skill with no pull** — `web_fallback` and
   `answered_without_data` both 0.0 on every trial. Unchanged, deliberately
   untouched, and still the reference failure the guards were built for.
